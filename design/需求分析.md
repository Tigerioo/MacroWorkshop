# 宏工坊需求分析：系统宏窗口扩展

状态：设计草案，供原型评审；游戏内集成方式和兼容性尚未实机验收。

## 1. 目标与定位

玩家在《魔兽世界：无限》中整理和制作宏时，继续使用游戏自带的宏窗口。宏工坊作为窗口的技能宏助手，帮助玩家选择技能、组合常用模板、预览命令，并将结果应用到系统当前选中的宏或创建新宏。

核心任务是减少宏语法的记忆和重复输入，并在可复用已有宏时不占用新宏槽。系统宏窗口保留通用／角色宏列表、原有编辑框、新建、名称和图标、删除及拖拽等职责；插件不再提供第二套主宏管理窗口。

## 2. 入口与窗口关系

- 玩家通过游戏原有 `/macro` 打开系统宏窗口，点击「宏工坊」展开或收起附着在旁边的助手。入口具体位置以客户端可用空间为准；窗口关闭时助手随之收起，重新打开后是否恢复由用户设置决定，首版默认收起。
- 系统宏窗口按需加载；插件需要在窗口加载后再接入。系统窗口移动、缩放、隐藏时，助手应保持可见、可达且不挡住原有操作；屏幕空间不足时调整位置或收起，不能假设右侧永远有空间。
- 系统新建／修改图标会展开图标选择器并占用额外空间。助手在该选择器出现时避让或暂时收起，关闭后恢复；具体方式以实际窗口位置与兼容性验证决定。
- 原型的系统窗口、宏和技能均为示例，不读取或修改游戏账号；界面展示反映设计意图，不冒充真实客户端截图。

## 3. 数据及安全边界

- 系统宏是唯一真源：系统窗口管理账号通用宏和当前角色专用宏；不读取其他角色专用宏或其他插件私有宏库。容量由客户端实际接口提供，原型数字仅为示例。
- 新建、写入、编辑和拾取按脱战可用设计；战斗或接口不可用时保留助手输入与预览并给出恢复提示。已有宏的执行仍须玩家主动按键。
- 系统在切换宏、切换通用／角色页或关闭窗口时可能自动保存编辑内容。扩展在填入前必须检查当前目标和编辑框是否有尚未处理的内容；展示明确目标及替换前后内容，由玩家决定继续或取消，不能静默覆盖。
- 宏列表或选中对象变化时停止使用旧目标：保留生成预览及可恢复的草稿，提示重新选择。不能只依赖旧编号；重复名称或完全相同正文也不能作为稳定身份保证。
- 删除及动作条交互沿用系统窗口原有行为；不另外实现删除，不宣称创建或拾取后已放上动作条。
- 无限服目标接口为 16001。窗口挂接、载入顺序、污点、战斗保护、系统自动保存与刷新、缩放和其他插件兼容性都待实机验证；焦点、鼠标指向及技能等级行为也须实测。

## 4. 功能与优先级

| 优先级 | 能力 | 验收条件 |
| --- | --- | --- |
| P0 | 系统窗口扩展 | 通过系统宏窗口打开和收起助手，系统列表与编辑操作仍可使用；助手不遮挡系统按钮。 |
| P0 | 选择技能 | 支持拖入技能；支持输入技能名称或 ID 作为替代入口，识别失败时保留输入并提示。 |
| P0 | 生成预览 | 支持普通、自动攻击、焦点、鼠标指向及自身模板，预览可复制；条件回退不暗示判断距离、视线或技能适用性。 |
| P0 | 填入当前宏 | 显示系统当前选中宏的名称、作用域和原正文；对比生成内容、明确替换后果并经用户确认后填入，不新建宏槽。系统自动保存时机须明确，不能误称必须点击插件保存。 |
| P0 | 新建宏 | 玩家明确选择新建、名称和作用域；满额、重名或失败时保留预览并说明恢复办法。创建成功后在系统窗口中可见，拾取与放置仍由玩家完成。 |
| P0 | 冲突和恢复 | 无选中宏、系统有未保存正文、宏列表变化、战斗、读取／创建失败和满额均有明确提示；输入与预览不因冲突消失。 |
| P0 | 避让与兼容 | 助手跟随系统窗口，图标选择器打开时不遮挡系统交互；界面状态变化不得覆盖系统草稿。 |
| P1 | 易用性 | 保留可复制预览和收起入口；支持键盘、拖放之外的技能输入及清晰的焦点状态。 |

不在本次设计内：独立的第二套宏管理窗口、自动战斗、自动施法、跨角色宏读取、在线分享及自动放置动作条。

## 5. 主要流程

1. 打开系统宏窗口，在通用或角色页选择已有宏，或准备新建；点击「宏工坊」展开助手。
2. 拖入或输入技能，选择模板与可选回退，检查生成预览。
3. 复用：选择「填入当前宏」，核对系统中当前名称、范围及原内容；若系统存在未保存修改，先在比较中呈现该修改并确认。确认后填入系统编辑框，遵循系统保存时机，不新增宏槽。
4. 新建：选择新建并确认名称与范围；系统宏栏不可用、满额或重名时保留预览，允许取消或改用当前已有宏。
5. 对象变化、战斗或失败时停止写入并保留内容；用户可重新选择、脱战重试或复制预览到系统编辑框。系统图标选择器打开时助手避让或收起。

## 6. 原型与验收

原型应同时呈现系统宏窗口和可展开／收起的助手：系统页切换、选中宏和编辑正文；技能与模板选择、预览、当前宏对比确认填入、新建、失败恢复、未保存内容保护与图标选择器避让均可操作。宏、容量、技能与状态为演示数据。

在当前原型中实际操作以上关键路径并检查界面，完成 Uncodixfy 审查。浏览器／WebView 验证只证明原型交互；游戏内原生控件、系统自动保存时机、客户端接口和插件兼容性仍须无限服实机验收。
