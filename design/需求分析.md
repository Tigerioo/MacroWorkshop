# 宏工坊需求分析

状态：设计草案，供原型评审；不代表无限服客户端已经验收。

## 1. 目标与使用场景

玩家在《魔兽世界：无限》中脱战整理宏：先找到游戏已有宏，再基于技能快速生成常用命令。一个工作区同时支持查看、修改、创建与复用，避免每次调整都新增宏、占满宏栏。

核心使用者是会使用技能和动作条、但不想记忆宏语法的玩家，也要保留直接编辑宏正文的能力。入口为游戏内 `/mw`；原型只演示交互，不连接游戏账户或读写真实宏。

## 2. 数据范围与限制

- 游戏原生宏是唯一真源，可读取账号通用宏和当前登录角色专用宏；不读取其他角色专用宏或其他插件的私有宏库。
- 分别显示两类宏实际占用与容量；原型数字和技能、宏内容均为示例。创建与编辑受游戏宏长度、名称、容量及权限限制，具体值以当前客户端运行结果为准。
- 创建、保存、删除和拾取按脱战操作设计；进入战斗时保留尚未保存的输入并禁用相应操作，脱战后允许继续。游戏内执行仍由玩家主动按键。
- 宏列表或内容被游戏、其他窗口改变后，不依赖旧编号写入；提醒玩家复制或保留草稿、刷新并重新选择目标。删除会影响该宏在动作条上的使用，必须明确后果并二次确认。
- 无限服目标接口为 16001。技能拖入、焦点与鼠标指向、技能等级、宏保存和运行限制仍需实机确认。目标有效不等于在施法距离内或视线可达。

## 3. 核心任务与优先级

| 优先级 | 任务 | 完成条件 |
| --- | --- | --- |
| P0 | 浏览已有宏 | 进入后能区分通用与当前角色宏、查看容量、选中宏并阅读完整正文。 |
| P0 | 修改或拾取 | 可编辑选中宏名称与正文并明确保存；保存不额外占用宏槽；玩家主动拾取并放到动作条。 |
| P0 | 生成常用宏 | 拖入技能或使用技能名称 / ID 作为替代入口，选择普通、自动攻击、焦点、鼠标指向或自身模板，实时查看可复制的正文。 |
| P0 | 创建或复用宏槽 | 明确区分创建新宏与写入指定已有宏；写入前展示目标名称、作用域和替换内容，进入待保存状态后由玩家保存。宏栏满时仍能复用已有宏。 |
| P0 | 删除与保护 | 删除有确认和取消；切换、关闭或刷新前保护未保存修改；已有宏内容不会被静默覆盖。 |
| P0 | 异常与恢复 | 宏栏满、重名、无效技能、客户端读取失败、战斗、列表变化时保留输入，指出可执行的下一步。 |
| P1 | 快速查找 | 宏较多时支持按名称搜索；列表为空或搜索无结果时说明状态。 |

不在本次设计内：自动战斗、自动施法、跨角色读取、在线宏库分享、自动将宏放上动作条。宏是否适合某个技能或目标，仍由玩家结合游戏实际判断。

## 4. 主要流程

1. 打开宏工坊，查看当前角色可访问的宏，按通用或角色切换；选择宏查看、编辑或拾取。
2. 选择「新建宏」，拖入技能或输入技能名称，选择模板并检查预览。
3. 选择「新建宏」或「写入已有宏」：前者检查容量和重名；后者明确选择目标、确认替换范围，先进入待保存编辑态。
4. 保存后给出真实结果；玩家选择拾取，再手动放入动作条。保存成功不能表述为已放置。
5. 发生冲突或失败时保留编辑内容，给出刷新、重新选择或复制的路径；删除单独确认，允许取消。

## 5. 原型与验收

原型是游戏内桌面窗口的交互示意，采用本地示例数据。应可操作：作用域切换、搜索与选择、编辑保存、技能选择与模板切换、创建、写入已有宏、删除确认及拾取反馈；还需能查看空结果和未保存修改保护。原型中的模拟状态与真实游戏数据清楚区分。

原型完成后，在浏览器中实际查看并操作上述关键路径，对照 Uncodixfy 检查信息密度、必要提示和操作可达性。浏览器验证只证明原型体验；真实插件接口、实际布局及游戏内行为必须在无限服客户端另行验收。
